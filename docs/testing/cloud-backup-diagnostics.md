# 云备份诊断与可靠性验收

本手册对应 `improve-cloud-backup-reliability`。诊断只定位技术失败阶段，不收集用户备份或身份。此处“已实现”不代表目标设备已验收；最终验证记录见文末。

## 1. 已核验的 SDK 契约

实现基于本机 HarmonyOS SDK **26.0.0.105 / API 26**，不提高项目最低兼容版本。

| API | 本机声明契约 | 边界 |
|---|---|---|
| `fileIo.writeSync` | 参数为 `ArrayBuffer \| string`；返回写入长度 | `Uint8Array` 必须转换有效视图；短写须继续补齐，零进展失败 |
| `WriteOptions.offset` | 文件偏移，不是输入 buffer 的视图偏移 | 不能把 byteOffset 错当文件 offset |
| `fileIo.moveFile(src,dest,1)` | 目标存在时报错，API 9 起可用 | 不支持分布式目录，未承诺云目录原子性；云环境必须真机验证，失败不回退成覆盖写入 |
| `fileIo.mkdtemp` | 创建唯一目录 | 用于持有本次创建文件的所有权，不用不存在于 SDK 的 EXCL 常量 |
| `CloudFileCache.start` | 仅确认任务启动 | 主动缓存需同实例/目标确认终态；终态失败且无在途工作时仍允许普通读取，不把缓存成功当作读取硬前置 |
| `CloudFileCache.stop` | 取消当前下载 | 取消失败或未结算须保留在途保护，不能通过新实例绕过 |
| `FileSync.start` | 接受同步请求 | 不是本次备份或删除在云端完成的证明 |
| `FileSync.on/off('progress')` | `SyncProgress` 只有 state/error | 监听和 start 共享实例；全局 COMPLETED 不承诺某一文件已经同步 |
| `systemDateTime.getUptime(STARTUP,false)` | 单调毫秒数，包括休眠 | 诊断开启时间不使用可被调校的系统日历时间 |

官方端云文件协同文档允许普通文件接口访问云目录，显式缓存不是读取许可的唯一来源。不得以 location=2 或预缓存失败直接跳过普通读取，也不得推出“删除必须先下载”。本变更对无冲突删除不主动下载；主动缓存已明确结束（含失败终态）且没有未确认 I/O 时，读取及恢复继续尝试普通文件读取。真实在途/取消未确认仍阻断冲突操作。

## 2. 诊断开关

开发者选项中的“云备份诊断”默认关闭。用户手动打开后仅对本次进程有效，最长十分钟；不写入偏好、不绑定通用调试开关、不自动上传。

关闭或到期只停止详细事件；默认模式可能保留经过同一隐私白名单校验的最小、去重限频失败摘要。关闭不会擦除已经进入系统日志的事件。旧异步上下文不能借新开启的会话继续输出。

- 详细模式每操作最多 32 条、每会话最多 256 条，预留终态/截断标志。
- 默认摘要每类每分钟最多一次、十分钟最多 32 条。
- 批量只记录有界代表性失败，不输出完整逐文件成功清单或省略条数。
- 时钟或诊断记录器异常不改变备份业务结果，不用原始日志兜底。

## 3. 允许与禁止输出

固定标签为 `CloudBackupDiag`，版本字段为 `v=1`。事件字段由固定 stage 白名单限制，并由采集端再次校验。

允许：固定阶段和结果、白名单错误域/码、归一化状态、技术布尔值、进程内临时操作号和粗耗时桶。URI 只比较是否匹配，写入只判断是否完整/是否为空，不打印判断依据。

禁止：账号、unionId/openId/ODID、设备名称、令牌/发行者/账号名称、OTP、密钥和凭据、图标包 UUID/名称/列表、备份正文/密文/header、salt/IV/签名/摘要、文件名/路径/URI，以及这些信息的哈希、后缀、编码或其他指纹。也不记录内容数量、准确字节数、备份时间、绝对时间和精确耗时。

禁止输出原始异常消息、堆栈、cause、整个对象、JSON.stringify(error) 或自定义 toString/toJSON。未知错误记为固定 UNKNOWN，不因排障困难临时放宽限制。

### 阶段定位

| 阶段 | 如何解释 |
|---|---|
| DEVICE_INFO | 身份或名称是否可用，不含实际值 |
| FS_PREPARE / FS_STAGE / FS_ENCODE / FS_STAGE_MOVE | 路径前置、暂存目录/凭据、编码与暂存移动失败，不含路径或内容 |
| FS_OPEN / FS_WRITE / FS_CLOSE / FS_VERIFY | 文件打开、参数种类、完整写入、关闭及读回校验 |
| TEMP_CLEANUP | 仅本操作确知拥有或本安装登记产物的清理结果，不输出凭据或账号绑定 |
| WRITE_END / PUBLISH_END | 本地完整内容与正式发布是否成功 |
| CACHE_START / CACHE_PROGRESS / CACHE_END | 启动与匹配终态分开；不含 URI/进度量 |
| CACHE_STOP / CACHE_DRAIN | 在途任务是否可靠停止 |
| READ_END / HEADER_PARSE | 读取失败和格式异常分开；后台摘要保留同一白名单的数值码，未知数量不等于零 |
| RESTORE_BEGIN / RESTORE_DECRYPT / RESTORE_VALIDATE / RESTORE_END | 请求、无法解密、载荷格式与落库结果分开；无法解密不直接判损坏 |
| ACCOUNT_STATE / ACCOUNT_AUTHORIZE / ACCOUNT_INIT / TIME_PARSE | 相邻账号与初始化固定技术结果，不输出原始异常 |
| DELETE_GUARD / UNLINK_BEGIN / UNLINK_END | 是否真正尝试删除，或在途保护阻断 |
| ICON_CLEAR / CLEAR_END | 图标及令牌清理结果，部分失败不等于全失败或网络故障 |
| SYNC_START / SYNC_STATE | 提交接受与全局同步状态，不推断单次远端完成 |

## 4. 安全采集

只运行 `scripts/collect-cloud-backup-diagnostics.mjs` 支持的参数，先执行 `node scripts/collect-cloud-backup-diagnostics.mjs --help` 查看用法。不要将全量 `devecocli log`、原始 hilog、设备列表或故障日志直接贴进 issue。

采集器通过 hdc 管道在内存处理，只保留匹配标签、版本、字段和值白名单的事件，并重新序列化。系统日期、PID/TID、设备标识等前缀被删除；其他 SDK/系统/应用输出和非法诊断行被丢弃；原始 stdout/stderr 不直接打印或保存。设备命令失败仅返回固定错误类别。

输出文件不得覆盖已有文件，不默认保留原始副本，也不联网。分享报告是维护者的显式动作。SDK 和系统自身的日志不由本应用控制，因此不承诺“设备原始日志完全无隐私”；安全边界是本应用规范化事件及经校验的报告。

- Node 采集测试及 Hypium 诊断测试注入合成身份、路径、凭据、非法码、恶意 toString/toJSON、嵌套错误和混合系统日志；输出不得出现哨兵或其编码变体。
- LocalUnit 不验证真实 fs/crypto/Base64/时钟；这些系统功能必须使用受控 ohosTest。所有 test suite 必须注册，名字唯一。

## 6. 真机安全约束与用例

只使用专用测试账号或明确可丢弃的测试数据。不要卸载、清数据、触发真实用户“清空所有”，或将真实令牌导入测试用例。

`CloudBackupIo.test.ets` 仅使用测试拥有的本地临时目录；`CloudBackupCloudLifecycle.test.ets` 只有测试参数 `cloudBackupOwnedFixture=true` 时注册，测试只操作本次唯一目录中的合成密文文件，不接受任意路径参数、不扫描清空用户备份。该用例验证云目录写入/发布/删除请求，不自动伪造 location=2，也不代表双设备验收完成。

### 必须分别验收

1. 本地真实写入：非 ASCII、非零 byteOffset 视图、读回一致、header 有效、旧格式可读、失败不覆盖旧文件。
2. 仅云端读取：由另一测试设备上传且本设备未缓存，确认待获取/读取失败/损坏三种状态不混淆。
3. 仅云端删除：使用明确的合成条目，确认没有先下载；记录 unlink 是否执行和同步是否提交。
4. 异常：断网、空间不足、缓存超时、stop 失败、同步启动失败、图标清理失败、重复点击和自动备份重入。
5. 范围：本设备、同名旧设备、全部、单条其他设备/未知来源；按设备时图标失败保留必要归属证据，重启可原范围重试。
6. 双设备：同一合成备份在第二设备同步后消失；不要把之后新创建的备份当成旧文件复活。真实条目标识只在本地人工对照，不写入诊断报告。
7. 界面：详情/确认/取消、深浅色、光感开关、最低兼容能力、大字体和底部安全区。截图只包含合成内容。
8. 诊断：开启/关闭/到期/休眠恢复/重启；默认摘要仍受白名单和限频约束，原始数据不进入采集文件。

无设备或第二设备时，将相应项标为“未执行”，不能用 start 成功或模拟测试替代。

## 7. 回退边界

本变更不修改备份持久格式，不迁移密钥，不改变 ASSET + 加密 KV 双写及三重迁移验证。出现兼容问题时停止发布并保留已有有效备份。业务/UI 回退必须保留日志隐私收敛，不恢复设备标识或原始异常输出；不得通过重新启用错误写入、无条件缓存删除来掩盖失败。

## 14. 图标包状态“元数据尚未确认”永久显示修复（2026-10-11）

### 现象与根因（真机实证）

用户报告华为云备份详情页“图标包备份”自云修复系列合入后一直显示“元数据尚未确认”。在 Mate 90 Pro Max（API26）开启云备份诊断会话取证：

- 打开详情页：`kind=ICON stage=READ_END result=FAIL reason=NOT_FOUND errorDomain=FS code=13900002`（ENOENT）——云端目录不存在 `icon_packs_sync_meta.json`。
- 触发一次“立即备份”全绿（含 `ICON_IO OK`、`SYNC COMPLETED`、`partialFailure=false`），但备份后一秒状态检查仍 ENOENT。

根因是两段行为的组合矛盾：`doBackupIconPacks` 对无图标包内容（`icon_packs/`、`user_icons/` 均空）按设计短路返回成功、从不写出伴生元数据；而状态显示以“读到合法元数据”为前提，“未备份/无图标包”分支排在 `metadataKnown` 门控之后且依赖其为真。因此“从未备份过图标包”这一确定状态被永久折叠成“尚未确认”。改动前同 ENOENT 回退本地注册表数据展示，所以旧版本不显现。

### 修复

- `IconPackBackupStatus` 新增 `metadataAbsent`：仅当伴生元数据 **stat** 明确 ENOENT（`isMissingFile` 只认 13900002）时为真；读取/缓存阶段的 ENOENT（如并发删除的 TOCTOU）仍归未知态。诊断侧该确定缺失路径**不产生任何行**：ICON 批次类只让失败事件可见，非失败的 `ICON_IO BEGIN`/`READ_END OK` 同样被丢弃，因此“已运行且确定缺失”“读取成功”“加载未触发”三者在该操作的诊断流中同为零输出、不可区分；仅未知态会记 `READ_END FAIL`。排查时不能把“没有 ICON 行”直接当作触发间隙回归。
- `ShowCloudSyncDetailsPage`：`metadataAbsent && !exists`（zip 与元数据都不在）时状态显示“未备份”、上次备份显示“从未”；其余未知情形（文件在但读取/校验失败、有 zip 无元数据）仍如实显示“元数据尚未确认/未知”。不回退本地注册表数据冒充云端状态。
- 已知预期噪音：`doCheckCloudBackupNewer`（冷启动自动恢复检查）对同一 ENOENT 仍走 `READ_END FAIL reason=NOT_FOUND` 限频摘要，且“从未备份”设备无 5 分钟去抖短路、每次冷启动可能记一次。功能正确（不触发恢复），诊断会话中出现该行不代表本修复失效。
- 页面轮询在状态未决（未读到、也未确认缺失）时补拉：含打开时首次直连加载在内**总共最多 5 次实际尝试**（轮询补拉至多 4 次），忙碌/清理/加载中仍被既有守卫拦截，已决出或达上限即停。
- LocalUnit 新增三分支用例：元数据与 zip 均缺失→`metadataAbsent=true` 且不发起缓存/读取；仅 zip 在→`metadataAbsent=true` 但保持未知态展示；stat 非 ENOENT 失败→保持未知态。既有读取失败用例补 `metadataAbsent=false` 断言锁定三态语义。

### 边界

- “从未”表示云端当前无图标包备份产物且元数据确定缺失；若本设备曾备份、产物其后被他处清空，仍会显示“从未”，不追溯历史（第三轮评审 P2-1 边界）。
- 真机取证时触发过一次真实“立即备份”（当日第二条记录，轮换上限内）；修复后的界面显示待下一次设备验收复核，未在本节宣称已完成。

### 触发间隙与有界补拉（同日补充，结论已被第 15 节修正）

真机复核曾怀疑图标状态加载触发不可靠（诊断会话中 ICON 记录不出现）。**该推断有误**：修复后确定缺失路径在诊断侧零输出（见上节），“无 ICON 行”与“加载未跑”不可区分，实际加载一直在执行。保留有界补拉（含首次总共最多 5 次实际尝试）作为对瞬态守卫拦截的防御，不属于本缺陷的必要修复。

真因：fac0af6 把图标包状态行从旧版响应式 `Text(this.getIconPackStatusText())` 改为 `this.StatusValue(label, value)` @Builder 按值传参。ArkUI @Builder 值参数不随状态变化刷新，行渲染冻结在首次构建值（初始未知=“元数据尚未确认”）。此前两轮“加载未跑”的判断均被修复后 absent 路径的诊断静默性误导。

修复：图标包“备份状态/上次备份/来源设备”三行改为直接绑定状态的内联 Column/Text（与 StatusValue 同样式），状态变化即时刷新。仅改图标区；页面其他 StatusValue 行（如全局云同步状态）存在同类冻结，属 fac0af6 既有问题，未在本修复扩大范围，留待后续单独处理。

**真机验收（Mate 90 Pro Max，修复构建保留数据安装）**：打开华为云备份详情页，图标包备份显示 **“未备份 / 从未备份”**（修复前：元数据尚未确认/未知），页面其余区域正常。当日第三、四轮设备操作：2 次 ohosTest 只读探针（各启动一次应用）、1 次追踪构建安装、1 次修复构建安装与 UI 复验；探针与追踪代码已从工作树移除，未进入提交。
